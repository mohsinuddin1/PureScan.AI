Why Google Search Console Refuses to Index Your Pages Properly

The root cause of weak indexing on scaningredients.com is not a mysterious Google penalty—it is a classic international duplicate-content and rendering collapse visible directly in Google's live search index. When querying Google for exact domain matches, four European locale URLs—/sv (Swedish), /lt (Lithuanian), /ru (Russian), and /lv (Latvian)—all render a localized <title> tag, yet their indexed body snippets are the exact same English sentence: Klar (formerly PureScan AI) is a mobile application for iOS and Android that uses artificial intelligence to scan food and cosmetic product...

Even user testimonials on /sv appear in English in Google's cache. Per Google Search Central's multi-regional documentation, Google determines page language from the visible rendered content, not the URL folder or HTML lang attribute alone. When every locale folder serves untranslated English fallback text (usually because translations hydrate client-side in JavaScript after initial paint, or because static sections like FAQs and testimonials stay in English), Google groups those URLs as near-duplicates. In Google Search Console's Page Indexing report, this directly produces Duplicate, Google chose different canonical than user, Crawled – currently not indexed, and Discovered – currently not indexed—starving major markets like /de, /fr, /es, /it, and /ja of crawl budget.

Three secondary blockers compound the problem. First, automated direct browsing of scaningredients.com was blocked during this audit, which strongly suggests an aggressive CDN/WAF bot rule or edge challenge that can also block AI crawlers (OAI-SearchBot, PerplexityBot, ClaudeBot) and slow Googlebot rendering. Second, high-intent footer comparison pages (Klar vs Yuka, Klar vs EWG, Klar vs Think Dirty, Klar vs Bobby Approved—visible in the footer of /blog/8-how-to-scan-food-and-skincare-products) are not appearing in Google's index. Third, brand identity is split across four names—scaningredients.com, Klar, PureScan AI, and Exposr Klar (Google Play / Apple App Store)—while the Google Play listing still uses a personal Gmail address (mohsinuddin64@gmail.com), weakening E-E-A-T trust for a health-adjacent YMYL app.

How to Rank in Every Country With Contextual Localization

Using contextual, culturally adapted phrasing instead of literal machine translation is a genuine competitive advantage—especially in food and skincare, where shoppers search using local regulatory terms rather than English translations. However, Google cannot reward contextual copy if crawlers only see English fallback text or conflicting canonical signals. Execute four technical rules to unlock every target country:

1. Server-Render 100% of Localized Text

Every element inside the initial HTTP response for /sv, /de, /fr, /es, /lt, /ru, /lv, /ja, and /hi—hero copy, feature cards, testimonials, FAQ accordions, navigation, footer, and JSON-LD—must render server-side (SSR/SSG) in that exact language. Zero English fallback strings. Verify with curl -s https://scaningredients.com/sv and Google Search Console's Test Live URL → View Tested Page → HTML.

2. Bidirectional hreflang + Self-Referencing Canonicals

Each localized URL must point its rel="canonical" to itself (e.g., https://scaningredients.com/sv), never back to the English root. Every locale must declare full reciprocal rel="alternate" hreflang="..." links to every other locale plus hreflang="x-default" pointing to https://scaningredients.com/, following Google's localized versions spec.

3. Map Contextual Search Vocabulary by Region

Do not translate "harmful additives" word-for-word. Target local search habits: EU/Nordics search E-nummer / E-Nummern (E171, E621, E250) and INCI; US searches seed oils, Red 40, ultra-processed foods, Yuka alternative; UK searches UPF scanner, HFSS; India searches FSSAI INS codes, palm oil checker, maida/sugar scanner; MENA/SEA searches Halal E-code scanner (E120, E471).

4. Localize Slugs & XML Sitemap Annotations

Keep root locale prefixes clean (/de/, /fr/, /es/) and localize high-value landing slugs (e.g., /de/inhaltsstoffe-scanner, /es/escaner-ingredientes) where your CMS supports it. Declare every localized URL cluster inside your XML sitemap using xhtml:link alternate tags and submit one sitemap index in Google Search Console and Bing Webmaster Tools.
